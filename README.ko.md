# t3code-sync — T3 Codex 자동 갱신

**Windows 미리보기 버전입니다.** T3 Code 0.1.9 / 데이터베이스 마이그레이션 81 및 지정된 스키마에서 검증한 로컬 실행 도구입니다. Linux와 macOS는 아직 지원하지 않습니다. T3 Tools 및 OpenAI와 무관한 독립 커뮤니티 도구입니다.

[Windows 다운로드](https://github.com/IEDGEI/t3code-sync/releases/tag/v1.1.0-windows-preview) · [English](README.md) · [복구 및 제거](docs/RECOVERY.md)

## Windows 설치

1. Python 3.9 이상과 Node.js 22.13 이상을 설치하고, T3와 Codex를 한 번 실행합니다.
2. T3에 대상 프로젝트를 추가합니다. 같은 프로젝트에 속한 누락 대화는 자동으로 가져옵니다.
3. [설치 ZIP](https://github.com/IEDGEI/t3code-sync/releases/tag/v1.1.0-windows-preview)의 압축을 풀고 `Install.cmd`를 실행합니다. **바탕화면에 T3 Code (Auto Sync) 바로가기가 자동 생성됩니다. 직접 만들 필요가 없습니다.**
4. 설치 후 T3를 완전히 닫고 바탕화면의 **T3 Code (Auto Sync)**로 실행합니다.

설치 프로그램은 T3·Python·Node.js 위치와 T3 데이터 호환성을 확인합니다. 런타임을 자동으로 다운로드하지 않습니다.
설치 패키지는 프로그램만 포함하며, 컴퓨터 사이의 대화나 파일을 전송하지 않습니다.

## 사용

**T3를 완전히 종료한 뒤 바탕화면의 T3 Code (Auto Sync)로 실행하세요.** 앱을 열기 직전에 이미 가져온 Codex 대화의 새 메시지를 반영합니다.
T3가 실행 중이면 기존 창을 열고 갱신을 다음 실행으로 미룹니다. 백그라운드 T3 서버도 종료되어 있어야 합니다.

| 실행 방법 | 자동 갱신 |
| --- | --- |
| 전용 T3 Code (Auto Sync) 바로가기 | T3가 완전히 종료돼 있을 때 실행 |
| 설치 프로그램이 연결한 기존 바탕화면·앱 폴더 아이콘 | 같은 조건에서 실행 |
| 원래 T3 실행 파일, 변경되지 않은 시작 메뉴·작업표시줄 아이콘 | 갱신기를 거치지 않음 |

설치 프로그램은 기본적으로 감지한 T3 실행 파일을 직접 가리키고 추가 인자가 없는 기존 바탕화면·앱 폴더 바로가기도 자동 갱신에 연결합니다. 원래 바로가기는 백업합니다.
추가 인자가 있는 바로가기는 유지하며, 시작 메뉴·작업표시줄 아이콘은 변경하지 않습니다. **어떤 아이콘인지 확실하지 않으면 전용 바로가기를 사용하세요.**
`-SkipExistingShortcuts` 옵션을 쓰면 기존 아이콘은 유지하고 전용 바로가기만 생성합니다.

기존 설치된 Python 3.9 이상과 Node.js 22.13 이상의 기본 SQLite 기능을 사용합니다. 네트워크 요청이나 추가 패키지 설치는 없습니다.

## 기존 설치 업데이트·복구

새 ZIP을 내려받아 압축을 풀고 **Install.cmd를 다시 실행**하면 설치된 갱신기를 교체하고 전용 바로가기를 다시 만듭니다.
**ZIP 다운로드나 GitHub 소스 갱신만으로 이미 설치한 프로그램이 바뀌지는 않습니다.**

대화가 갱신되지 않으면 T3를 완전히 종료하고 전용 바로가기로 다시 실행한 뒤, `%USERPROFILE%\.t3\codex-autosync\last-sync.json`을 확인하세요. 사용자 지정 데이터 폴더를 쓴다면 해당 폴더의 상태 파일을 확인합니다.

- `messages`: 이번에 추가한 메시지 수
- `deferred_t3_running`: T3가 실행 중이어서 갱신을 미룬 상태
- 대화별 `skipped`: 원본 기록 없음, 기록 불일치 등 건너뛴 이유

새 대화는 Codex의 현재 소속 폴더가 기존 T3 프로젝트 하나와 일치하면 자동으로 가져옵니다. 완전히 새로운 프로젝트는 먼저 T3에 추가하세요.

## 갱신 범위

- 기존 T3 프로젝트에 빠진 Codex 대화를 가져오고, 완료되거나 중단된 턴의 사용자·답변 메시지를 추가합니다.
- Codex의 현재 프로젝트 정보를 사용합니다. 원본에 옛 폴더가 남아 있어도 현재 소속으로 연결하며, 조건을 만족하는 기존 가져오기 대화의 프로젝트 연결도 수정합니다.
- Codex의 원본 데이터는 읽기 전용으로 접근합니다.
- Codex 내부 설정, AGENTS 지침, 도구 출력 등은 새 메시지로 추가하지 않습니다.
- 새로운 T3 프로젝트 생성은 Welcome 화면에서 수동으로 진행합니다. 보관된 Codex 대화, 하위 에이전트·Guardian 대화, 삭제한 T3 대화는 자동으로 추가하지 않습니다.
- T3에서 이어 쓴 대화, 원본이 달라진 대화, 원본이 없거나 압축된 대화는 건너뛰고 이유를 로그에 기록합니다.
- 기존 가져오기에서 빠진 과거 메시지를 복구하거나 이미지·도구 실행 내역을 복제하는 도구는 아닙니다.
- 한 번에 최대 500개 메시지를 추가합니다. 남은 메시지는 다음 실행 시 처리합니다.
- T3의 버전/DB 구조가 지원 범위를 벗어나면 기록을 수정하지 않습니다.

처음 가져올 때는 **첫 메시지와 최근 기록을 합쳐 최대 200개**를 보관합니다. 생략한 과거 메시지가 있으면 대화 안에 안내를 표시하며, 원본은 그대로 유지합니다. 이후의 새 메시지는 다음 실행부터 이어서 반영합니다.
T3에서 실행한 작업이 있거나 브랜치·worktree 설정을 붙인 대화는 자동으로 프로젝트를 옮기지 않습니다. 프로젝트가 여러 개 일치하거나 다른 T3 대화가 이미 같은 원본을 소유한 경우도 건너뜁니다.

## 대용량 기록 처리

원본 파일의 512MiB 제한을 없애고 작은 조각으로 읽으면서 필요한 텍스트만 추출합니다. 이미지 데이터와 도구 출력은 저장하지 않습니다.
선택한 문자열은 16MiB, 선택 기록·구조는 64MiB 예산으로 제한하며, 초과하면 해당 대화를 건너뛰고 이유를 기록합니다.

첫 처리 후 압축 캐시에 필요한 기록과 읽은 위치를 저장합니다. 다음 실행에서는 새로 완성된 기록만 해석합니다. **기존 부분이 수정되지 않았는지 SHA-256으로 검증할 때는 앞부분의 바이트를 다시 읽습니다.**
파일 교체·축소·과거 내용 변경 또는 캐시 손상을 발견하면 처음부터 다시 처리합니다. 아직 작성 중인 마지막 줄은 다음 실행에서 다시 읽습니다. `--preview`는 기존 캐시를 읽을 수 있지만 변경하거나 새로 만들지 않습니다.

## 저장과 복구

설치 경로: `%USERPROFILE%\.t3\tools\codex-autosync`

실행 기록과 백업: `%USERPROFILE%\.t3\codex-autosync`

- `last-sync.json`: 최근 결과, 대화별 추가 메시지 수, 건너뛴 이유
- `sync.log`: 실행 결과 기록. 대화 본문은 기록하지 않습니다.
- `backups\statev2-before-sync-*.sqlite`: 매 변경 전 무결성을 확인한 전체 DB 백업
- `shortcut-backups`: 변경 전 바로가기
- `source-cache`: 선택한 대화 텍스트와 읽기 위치를 보관하는 압축 캐시. 원본 전체를 복사하지 않습니다.

프로그램은 정규 이벤트, 화면용 projection, 검색 인덱스, 타임라인 순서와 체크포인트를 하나의 트랜잭션으로 반영합니다.
트랜잭션 중 T3가 켜지거나 원본 기록이 변경되면 쓰기를 취소합니다.

복구가 필요하면 T3를 완전히 종료한 뒤 현재 `userdata` 폴더를 별도로 보관하고,
백업 DB를 `%USERPROFILE%\.t3\userdata\statev2.sqlite`로 복원합니다.
기존 WAL/SHM이 있다면 함께 별도 보관해야 합니다. 실행 중인 DB에 백업을 덮어쓰지 마세요.

자동 갱신을 끄려면 원래 T3 실행 파일로 실행하거나 `shortcut-backups`의 기존 바로가기를 복원하세요.

## 개발과 진단

```powershell
python "$env:USERPROFILE\.t3\tools\codex-autosync\autosync.py" --preview
python "$env:USERPROFILE\.t3\tools\codex-autosync\autosync.py" --apply
python "$env:USERPROFILE\.t3\tools\codex-autosync\autosync.py" --launch
```

저장소 루트에서 개발 검증 및 설치:

```powershell
python -m unittest discover -s tests -p "test_*.py" -v
python scripts/build_package.py
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 -Preview
.\scripts\Install.cmd
```

실행 코드는 `src/`, 설치·패키징 스크립트는 `scripts/`, 테스트는 `tests/`, 보조 문서는 `docs/`에 있습니다.

`config.json`에는 T3 실행 파일, T3/Codex 데이터 폴더와 결과 저장 폴더를 지정합니다.
설치 프로그램은 `T3CODE_HOME`과 `CODEX_HOME`을 우선 사용하며, 지정하지 않으면 사용자 폴더의 `.t3`와 `.codex`를 사용합니다.
T3 업데이트 후 DB 구조가 바뀌면 호환성을 재검증해야 합니다.

구현 시 로컬 설치본의 `AgentSessionImporter` 이벤트 형식과 Codex JSONL 기록 형식을 확인했습니다.
